# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start from the punch-in's own naive/server-local date and clock, not from IST on the attendance date. Wrong on an overnight shift and wrong whenever the server time zone is not IST. | Server in UTC: a 10:05 IST punch-in (shift 09:30) arrives as 04:35, the "start" becomes 09:30 on that same naive clock, the difference is negative and the result is 0 instead of 35. Late arrivals are reported as on time. | `shift_bounds()` builds the start as an IST datetime for the attendance date. |
| 2 | `compute_late_minutes` | Floors to whole minutes *before* the grace test (`minutes > 10`). 09:40:01 floors to 10, so it returns 0, but R2 says 10. Microseconds are not truncated either. | Punch in at 09:40:01 on a 09:30 shift: expected 10, got 0. | Compare **seconds** (`> 600`), then floor. Instants are truncated to whole seconds on input. |
| 3 | `compute_work_hours` | Python `round()` is banker's/float rounding; R4 requires half-up. No second truncation. | 9630 s = 2.675 h: `round(9630/3600, 2)` gives 2.67, R4 says 2.68. Near 4.50 this also flips the half-day decision. | `Decimal` with `ROUND_HALF_UP`. The half-day test uses the rounded value (R5). |
| 4 | `compute_overtime` | Ignores the 30-minute minimum (R3), so 5 minutes of overtime counts. The shift end is always on the attendance date, so overnight shifts are wrong. | Sample 1: punch-out at 18:35 returns 5, expected 0. Overnight 22:00-06:00 shift: end is computed on the wrong day. | `overtime_minutes()` applies `>= 30`; `shift_bounds()` adds one day for overnight shifts. |
| 5 | `punch_in` (date and time) | The date comes from `datetime.fromtimestamp` (server local time), not IST, and ignores the overnight rule R1. The naive local datetime is also written to MongoDB, which treats it as UTC, so the stored instant is off by the server's UTC offset. `if body.punched_at` treats `0` as "missing". | Server in UTC: a punch-in at 00:30 IST gets the previous date. An overnight punch-in at 05:00 gets the wrong day. | `attendance_date()` converts to IST and applies the overnight rule; instants are aware UTC datetimes; `is not None` check. |
| 6 | `punch_in` (unknown employee) | `emp` can be `None`, then `emp["shift_start"]` raises `TypeError` -> 500. | POST punch-in with an unknown `emp_code`. | Explicit 404 before any use. |
| 7 | `punch_in` (race) | check-then-insert with no unique index: two parallel requests both pass the check and both insert. | 20 parallel identical punch-ins give more than one 201 and duplicate documents. | Unique index `(emp_code, date)` created at startup; the insert itself decides, `DuplicateKeyError` -> 409. |
| 8 | `punch_in` (input and output) | `status` is a free string (accepts `ABSENT`, `foo`); `punched_at` accepts seconds, floats and negatives. The response returns `id` (an ObjectId string) and raw datetimes instead of epoch ms. | Send `status: "LEAVE"` -> 201. Send `punched_at: 1783312500` (seconds) -> accepted. | `Literal` status, strict int epoch-ms range (422), response built by `record_out()` (no id, ms values). |
| 9 | `create_employee` | check-then-insert race, so duplicate `emp_code`; naive local `datetime.now()` as `created_at`, returned as a datetime instead of epoch ms; no validation (emp_code format, email, shift pattern, `shift_start == shift_end`, invalid `joined_on`). | Parallel creates give duplicates. `joined_on: "2026-02-30"` -> 201. | Unique index + `DuplicateKeyError` -> 409; UTC ms `created_at`; pydantic patterns and validators -> 422. |
| 10 | `list_employees` | `skip = page * page_size` skips the first page (should be `(page-1)`); `total` counts the whole collection, not the filter; no sort, so order is undefined; `page=0`, negative or huge `page_size` allowed. | `page=1` returns the second page; `?department=HR` shows the total of all employees. | `(page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `Query(ge=1, le=100)` bounds. |
| 11 | `list_attendance` | Loads the whole collection into memory and sorts in Python (slow at 100k docs); the sort has no `emp_code` tie-breaker; `page=0` gives an empty or wrong slice; `date_from > date_to` and bad dates/status are not rejected; returns `_id` as `id` and raw datetimes, and omits `half_day`/`history` on legacy documents. | Time the endpoint with 100k records. Call with `page=0` (empty list instead of 422). | Database `find().sort().skip().limit()` backed by indexes; 422 validation; `record_out()` fills legacy defaults. |
| 12 | Whole file (datetimes) | `MongoClient` without `tz_aware=True` returns naive datetimes. Mixing them with aware IST values raises errors or silently shifts times by 5:30. | Subtracting a stored punch from an aware value raises `TypeError`. | `tz_aware=True`; `to_ms`/`from_ms` convert at the boundary with integer arithmetic. |
| 13 | `/health` | Always returns 200, even when MongoDB is down. | Stop MongoDB, call `/health`. | Pings MongoDB; 503 on failure. |
| 14 | Startup | No indexes at all: unique guarantees are missing and every query is a collection scan. | `explain` shows `COLLSCAN`. | `ensure_indexes()` in the lifespan hook, idempotent. |

**Looked at and judged fine**
- `load_dotenv()` with its default `override=False`: real environment variables already win.
- Returning 409 through `HTTPException` is the right mechanism; only the logic around it was wrong.
- The `localhost` fallback for `MONGO_URI` is only a development default; the grader's environment variable always takes priority.
